# CL原油：IB与LSEG分钟线差异调查

2026-11-12，按用户要求只读调查。当前证据更支持**成交纳入口径差异，尤其大宗成交／迟报打印**是主要方向，
不能把全部3.6654%差异登记为IB漏单，也不能据此删除LSEG迟报成交。
另有非迟报差异与IB合约历史覆盖范围问题，尚未全部归因。

## 范围与已排除的简单解释

2026年现有LSEG与IB原始快照，22个同规格CL合约、3,361,379个匹配分钟；
比较最多到2026-11-03 05:20 UTC，各到期合约更早结束。
匹配分钟LSEG净量77,843,376手，IB量74,990,096手，IB少2,853,280手，即−3.665411%。
只有匹配分钟参与这个百分比，未匹配分钟另计。

22个合约的净差均为负，2026年1月至11月各月净差也均为负，不能归结为一个错配合约或某一天。
例如已核定CLN26双方均为NYMEX、USD、1,000 BBL；不是微型合约与标准合约相差倍数的问题。
现有±1分钟标签探针中，22个合约都是不平移的收盘一致率不劣于±1分钟；
这不支持把整体偏移一分钟当作修复，也不证明IB服务端内部用哪一种时钟。

已对31,484个成交量不等的匹配分钟从Trade重新聚合，并应用同一可信改撤账本；
每分钟的净成交量均复现现有交付K线。
这证明本次K线实现与输入口径一致，不证明原始源的每个打印都最终有效。
在这22个合约的比较覆盖期，已核定改撤合计使笔数减少505、量减少121,013手；
这些合约当前账本仍有266条未确认改撤（其中264条在比较窗口内发布），原成交保留。详见[已应用改撤范围](../artifacts/cl_difference_20261112/applied_revision_scope.json)。

## 主要量差与迟报的关联

- 24,695个匹配分钟IB量较少，合计少2,899,137手；6,789个分钟IB量较多，合计多45,857手。
- 净少量中2,715,485手发生在“含跨分钟迟报”的分钟，占2,853,280手净差的95.1706%。
  这是分钟层面的关联，不表示这95.17%的每一手都已经识别为迟报或大宗。
- 仅对既有量不等的分钟作诊断：排除其中发布时间已经跨入后一分钟的TAS打印后，
  18,719个分钟的剩余量恰好等于IB。这组分钟对应2,637,133手净差，占总净差92.4246%。
- 若诊断阈值收紧为实际迟报至少60秒，则14,269个分钟量恰好等于IB，
  对应2,510,074手净差，占87.9715%；这批不等分钟整体仍有273,211手净差。

**92.42%只是选定差异分钟内的敏感性结果。等量分钟并未参加这次排除实验，
因此不能把这个比例外推成全局过滤正确率；迟报跨分钟也不等于成交无效。**
本轮没有改变任何Trade、RocksDB、K线或IB记录。
详细数字见[迟报诊断](../artifacts/cl_difference_20261112/late_attribution.json)、[按日差异](../artifacts/cl_difference_20261112/per_day.csv)、[按合约差异](../artifacts/cl_difference_20261112/per_contract.csv)。

## IB官方公开说明提供的解释边界

[IB官方旧版历史K线API文档](https://interactivebrokers.github.io/tws-api/historical_bars.html)明确写道：

> IB's historical data feed is filtered for some types of trades which generally occur away from the NBBO such as combos, block trades, and derivatives. For that reason the historical data volume will be lower than an unfiltered historical data feed.

这证明IB历史feed本身可能选择性过滤大宗等成交，所以“IB分钟线比LSEG少大宗量”可以是数据产品口径差异。
页面已提示旧文档弃用，不能据其自动断言当前数据库全部采用该接口及相同过滤条件。
MySQL快照保留了分钟值、合约、created_at等，没有请求接口、whatToShow、useRTH等参数，故这仍是有官方依据的主要解释方向。
抽查的3月／6月问题行created_at都是2026-10-20；created_at仅是落库时间，不能证明实际下载接口或最初采集时间。
因此也不能只说“实时来不及收到迟报，没更新K线”，就视为已经查清。
原文摘录与下载内容哈希见[官方说明来源](../artifacts/cl_difference_20261112/official_ib_policy.json)，HTML缓存仅留项目本地。

## 另发现：293列日包回源selector列序不兼容

调查时的旧版`tas_identity_select`固定把前5列解释为RIC、Domain、Date-Time、GMT、Type；
293列日包的实际前6列是RIC、Alias Underlying RIC、Domain、Date-Time、GMT、Type。
对6月10日10个已知Trade发布时间，旧版selector完整扫描14,758,172行／6,320,110,877字节，输出0行。
改用独立`rg -F`按相同10个时间筛选，再按原始293列表头解析，找回上文全部10条Block Trade。
用这10条值相同的重建CSV做短复现，旧版selector仍输出0行。
所以不能把selector的0命中当作“该源没有成交／取消”。

旧缓存已有正确daily源见证，不因此否定既有恢复结果。后续已修复表头识别，10条短复现全部找回；
这不代表历史零命中缓存已经全部回源，也未据此改写本次调查或已交付K线。
复现命令、原表头、扫描记录和模式哈希见[selector问题](../artifacts/cl_difference_20261112/selector_293_issue.json)，
10条短输入见[复现CSV](../artifacts/cl_difference_20261112/selector_293_repro.csv)，时间列表见[10个模式](../artifacts/cl_difference_20261112/june10_patterns.txt)。
主线新增全库处理直接只读扫描RocksDB，不依赖此CSV selector。

## 仍待核的事项

1. 核实本地IB分钟库实际采集接口及whatToShow／useRTH等参数，以区分API既定过滤和采集缺项。
2. 保留LSEG所有迟报／大宗原打印及现有净额K线；未确定关联的改撤不能猜删。
3. 对CLJ26等无显著迟报残差，以及CLH27跨度内单边分钟，进一步取得IB逐笔或下载／更新证据。
4. 用已修复的表头识别复核历史日包零命中缓存；旧0行结果不自动视为源中没有对应记录。

本轮只发布实际差异和问题证据，没有生成成功audit或验收回执。

## 主线后续修复：日包回源入口

本次调查后，主线已修复`tas_identity_select`：按传入header定位RIC／时间／Type，
兼容多一列Alias Underlying RIC的293列日包及无表头流，模式时间不再限制2026年。
既有10条短复现从0条恢复为10条；没有为验证重复扫描完整日包或年度源。
Python回源入口传入确切header，并只使旧日包的未验证零命中缓存失效；既有非零正确见证保留。
代码修复不代表历史所有零缓存已经回源，也未自动改写本次调查或交付K线。
