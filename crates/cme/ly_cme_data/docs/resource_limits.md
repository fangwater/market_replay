# 普通 bin 的程序资源预算

用户要求直接在程序层面限制，现不再强制cgroup，不需要root或管理员配置。
当前数据入口是独立Rust工具 `lseg-kline`，读取、状态解析和Parquet写入都在Rust内完成。
固定线程池、有界缓存、流式处理是主要控制；
普通Rust入口 ly_cme_run 加程序内监测，不通过service、systemd-run或scope启动。

## 当前预算

| 项目 | 设置 |
| --- | --- |
| 内存总预算 | 64 GiB |
| 提前停止阈值 | 进程RSS+swap之和达到60 GiB，预留4 GiB |
| 总进程及线程预算 | 32，包含普通父进程及其监测线程；观察到超过32时停止任务 |
| CPU亲和性 | 最多32核，不设置系统CPU配额 |
| 独立任务 | 共用互斥锁，不分别领取预算 |
| Rust工作单元 | 默认且最多2 |
| Parquet发布线程 | 固定8，独立于2个聚合线程；生产合计预计15线程 |
| 发布队列 | 全局16项，每RIC最多16项待确认；全部确认后才写RIC断点 |
| 状态写出批次 | 8192行 |
| RocksDB块缓存 | 每个打开的DB 64 MiB |
| 当前RIC分钟桶 | 最多530,000桶，处理完即释放 |
| BLAS／OpenMP／Rayon等隐式池 | 1 |

2026-11-13按用户提速要求分离聚合与发布。相同128个NFS日文件的两次小样本中，
串行写出分别6.186／5.696秒，8线程发布分别2.277／1.866秒（2.72／3.05倍）；
第二次16线程为2.353秒，未优于8线程，因此生产固定8，不继续扩大。
这些是小样本写盘时间，不能直接宣称全库端到端也提升相同比例。
发布仍逐文件同步、核对footer、以硬链接原子不覆盖发布，并保留首／中／末内容抽样。
故障或队列提交不能算完成；提前返回也等待本RIC已提交文件结束，不留脱离任务的工作线程。

历史Python工具导入DuckDB时会按整机CPU数创建默认池，晚设查询线程会先出现191个额外线程。
构建入口同时在NVMe生成小型CPU自动探测库；普通Rust父进程只给本任务后代设置LD_PRELOAD，
把glibc get_nprocs／get_nprocs_conf用于自动建池的返回值限定为1，避免导入阶段先扩张。
不改变系统CPU数、其它进程或手动配置的工作池。当前Rust数据工具不加载DuckDB或Python。
通过 scripts/build.sh 构建该库及Rust bin；缺少该库时入口报错，不静默无保护运行。

普通父进程约每250ms读取一次本任务及子进程资源。达到停止阈值或监测失败则停止任务，
只把实际异常写stderr，不发布成功audit或进度报告。正常命令退出时清理其遗留子进程。
身份发现只解析stat的PID／父PID／进程组／启动时钟，comm按字节处理，不解析无关进程的RSS。
PPID／PGRP按Linux有符号pid_t读取，退出过程出现的负值不与本任务组匹配；
但父子链可确认的任务后代仍计入，不能仅因PGRP为负而跳过资源统计。
实际成员的RSS／swap／线程数来自status，读取后再次核对PID启动时钟；退出竞争按ENOENT／ESRCH处理。
错误保留PID／路径／具体字段，并单独保存到NVMe runtime/failures，避免进度查询只能看到一个陈旧running状态。
子进程不得自行daemonize或脱离任务；既有管线均使用普通继承关系。
本机互斥锁在NVMe的 lseg_data/runtime/resource.lock，只存当前父进程身份，不是对外交付文件。
持锁期间另一个独立任务会报错，程序祖先内的工作进程共享同一个任务。

这是程序预算和采样保护，**不是内核硬配额**：两次采样之间的大分配或建线程可能短暂超出目标。
RSS共享页会重复计数，未映射文件缓存不在RSS内；不能宣称严格限制全部机器内存。
需要绝对不可超出的进程树硬配额时仍须由操作系统提供限制，本轮不以此作为运行前提。

## 检查和入口

仅检查程序配置，不启动数据任务：

~~~bash
/mnt/nvme-raid0-28t/fanghaizhou/cargo-target/market_replay/release/ly_cme_run --check
~~~

输出明确标记 kernel_hard_limit=false；配置检查不等于大数据负载已验证。
`lseg-kline`及原生 tas_sparse_extract／默认导出bin会自动经普通Rust父进程启动，
在读取数据之前核对实际祖先、进程启动时钟及持锁状态，不信任单独的环境标记。
其它旧工具使用 ly_cme_run -- <bin> <参数>。

当前全量续跑入口（普通前台程序）：

~~~bash
lseg-kline run --workers 2
~~~

无需执行此前的管理员cgroup配置步骤，也没有修改系统cgroup、其它用户或编辑器资源。

## 有界处理的边界

状态直接从RocksDB iterator按RIC／时间合并，不生成行情JSON或额外排序数据集。
状态区间即时合并，详细session_status逐日以8192行写出，Qualifiers解码缓存限4096项／8 MiB。
当前RIC成交聚合保留最多530,000分钟桶，足以处理一年并接纳迟报及跨源顺序。
百万真实状态区间等容量边界超限明确失败，不截断、不忽略消息。
已完成稀疏分钟Parquet经源身份／CURRENT／footer核对后复用，仅投影RIC列建立行范围，
其后按选中行读取当前RIC，不为每个RIC重复解压全部价格列。
旧Python流程及接续进程已停止，不得恢复；当前入口、抽样方法及断点见[原生工具](native_kline.md)。
