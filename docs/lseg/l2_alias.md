# COMEX 金属 L2：`1` 开头的 Globex 代码（2026-11-27）

## 是什么

LSEG 把 COMEX 金属（GC、SI、HG、ALI）的盘口深度分两个家族发布：

| 家族（采购包） | 代码 | 有深度的时间 |
| --- | --- | --- |
| `comex_futures` | 正规代码，如 `GCZ2`、`GCZ24` | 2016–2023 的 Report 全为 0 条；2024-07-10 起有（ALI 2024-09-28 起） |
| `comex_globex_futures` | Globex 代码，前面加 `1`，如 `1GCZ2`、`1GCZ24` | 2015 起，到 2024-09-27 为止 |

2024-07-10 到 09-27 两个家族并行，之后 `1` 开头的停发。TAS 只用正规代码，所以 `1` 开头的合约只出现在 L2 里，交付盘上一直放在 `comex/<年>/1GC…/` 这类单独的目录下，没有和 GC 等合约关联。`l2_gaps.sqlite` 按正规代码检查，因此把 GC/SI/HG 2020–2023 记成了"Report Count 0"。preprocess 的 `future_supplement.md` 当时已写明"不能无条件删掉前导 1 后合并"，需要先核实是同一本盘口。

## 核实

对每个 `1` 开头的合约-年（`lseg_l2_alias plan`）：

- 取 3 个样本日（有正规代码 TAS 报价的第一天、中间一天、最后一天）。
- 把 `1` 开头 L2 每个网格点的一档买价和卖价，与正规代码 TAS `quote.parquet` 在前后 1 秒内的报价比对：有相同的，就算一致。
- 负对照：同品种、同一年、另一个月份合约的 TAS 报价。
- 判定：一致率中位数 ≥ 0.5，且负对照全部 ≤ 0.05，才算通过。

依据：

| 比对 | 一致率 |
| --- | ---: |
| 正对照：GCZ24 自己的 L2 和自己的 TAS（2024-08-15） | 0.7271 |
| 别名：1GCZ24 的 L2 和 GCZ24 的 TAS（同一天） | 0.7271 |
| 1GCZ24 和 GCZ24 两份 L2 直接比（同一天，12.9 万个网格点） | 99.3% 完全相同 |
| 负对照：别名和另一个月份合约的 TAS | 0.0000 |

TAS 报价只记录了一部分一档变化，所以正规代码自己比也到不了 1。

TAS 在样本日没有报价的远月合约没法核实，不交付，记为 `no_tas_quote_to_check`。

## 交付

`lseg_l2_alias deliver`：只对通过核实的合约-年，在正规代码当天没有 `l2_250ms.parquet` 的日子，从 `1` 开头的那份重新写一份：

- `ric` 列改成正规代码，其余各列逐值不变；
- 文件尾保留原有的键值，另加 `l2_alias_of=<1 开头的代码>` 和 `l2_alias_rule`；
- 按交付盘规则发布：临时文件、fsync、核对文件尾（行数、每个行组的 RIC、UTC 日范围）、硬链接，不覆盖任何已有文件；
- `1` 开头的原目录保留。

之后用 `lseg_catalog l2-sync --ric-years` 更新索引，再重建 `meta/l2_gaps.sqlite`（`l2_gaps_build.py` 加 `--aliases plan.csv --alias-delivered stage/delivered.tsv`）：

- 新表 `l2_aliases`：每个 `1` 开头的合约-年一行，记对应的正规代码、判定、样本日、一致率、负对照和补交付的日数。
- 补齐了的正规代码合约-年从缺口表里消失；没交付的那些，原因改为 `alias_unverified`（附判定和依据），补了但没盖满的为 `alias_partial`。
- 美债和 YM 的缺口行不变，原因仍是"从未订购"或"Report 为 0"。

## 2026-11-27 的核实结果

产物在 `/mnt/nvme-raid0-28t/fanghaizhou/lseg_data/artifacts/l2_alias_20261127/`（`plan.csv`）。2020–2024 年交付盘上共有 742 个 `1` 开头的合约-年：

| 判定 | 合约-年 | 待补的日文件 |
| --- | ---: | ---: |
| `pass` | 559 | 99,863 |
| `no_tas_quote_to_check`（样本日正规代码没有 TAS 报价，多是 ALI 和 HG 的远月） | 105 | 4,177 |
| `no_comparable_day`（`1` 开头的有数据的日子里，没有一天正规代码有报价且找得到负对照） | 73 | 2,825 |
| `fail` | 5 | 356 |

- 通过的按品种分：GC 每年 32–33 个，SI 30–31 个，HG 33–40 个，ALI 16–20 个（2024 年只补正规代码 07-10 以前没有 L2 的日子）。
- 5 个 `fail`：1HGG0、1ALIF1、1GCF1、1GCF2、1HGG24。别名一致率都在 0.75–1.00，但有一个样本日的负对照也高（0.06–0.87），多半是相邻月份当天报价相同（价差为 0），或远月两边都没怎么动。按规则不交付，没有放宽阈值。其中 GC 的 1 月、HG 的 2 月都不是活跃月份；ALIF1 只涉及 2021 年的 8 天。
- 没通过的合约-年，`1` 开头的原文件仍然在交付盘上，需要的时候可以直接读。

**交付（2026-11-27 UTC 09:14–12:12，8 个线程）：** 99,863 个日文件全部发布，失败 0 个，没有覆盖任何已有文件（日志 `stage/delivered.tsv`）。抽查 HGF3 2021-11-25：行数相同，只有 `ric` 列不同，其余各列逐值一致，文件尾有 `l2_alias_of=1HGF3`。随后 `l2-sync --ric-years` 刷新了 559 个 L2 目录（107,278 个文件，含 2024 年正规代码原有的文件），比如 GCZ2 现在 2020–2022 每年约 310 天。

**缺口表（`meta/l2_gaps.sqlite`，2026-11-27 重建并替换）：** 新增 `l2_aliases`（742 行）。2020–2023 年每年仍缺 L2 的金属合约：

  - 11-26 的交易所迁移让 159 行从 `review` 改到正确的交易所；

## 补不了的：美债和 YM

- **美债（TU、FV、TY、TN、US、AUL）2020–2024：** 采购目录只有 `summarised` 和 `tas` 两层，从未订购 L2（`l2_gaps.sqlite` 的 `not_in_any_package`），任何包里都没有，也没有别名代码。2025 年起有 Raw LL2。要补，需要向 LSEG 新提 L2 作业。
- **YM 2020–2024：** 已订购，但 Normalized LL2 的 Report 消息数为 0，Raw LL2 没有对应 Report，也没有别名代码。2025 年起才有。

这几年这些品种只能用持仓和成交量两个指标（见 [../cme_roll.md](../cme_roll.md)）。
