## 1. 目标与当前口径

用户提供分钟频率的目标仓位 Parquet，工作台从 MDL 原始行情模拟执行，比较 taker / maker 的实际仓位、成交成本和收益。

已明确：因子和规则属于下单执行层；策略目标仓位由用户提供。第一版采用简单成交规则，maker 以严格击穿成交，不建订单队列。

用户进一步确认：支持将品种级目标金额按当天生效的主力合约转换成整数手仓位，并估计交易成本。这项转换应能独立运行和导出，再将同一份按手目标交给 taker / maker 回测。主力切换时须显式处理平旧开新的移仓，不能只替换合约代码。

换月采用独立的固定执行算法 `maker_maker_roll_v1`：围绕新旧合约价差进行双边 maker 挂单，按成交后的实际持仓控制品种敞口；换月成本优化支持独立回测。它替代先平完全部旧仓再开新仓的默认移仓方式。

两种执行模式共享输入、账户和时间模型，都使用 MDL/ZMQ；分钟价格可用作因果参考和结果汇总。

第一版范围：CN 六所、实际期货合约、整数手数、净仓位、连续竞价、单个回测任务串行运行。集合竞价、组合和 EFP 不参与撮合；行情回放本身仍原样透传。

下表是引擎内部标准格式，允许通过上述宽表导入，不要求用户预先改文件。

| 字段 | 类型与含义 |
| --- | --- |
| `effective_ts` | 带明确时区的时间，或明确单位的 Unix 时间；该目标最早允许被执行层读取的时刻 |
| `exchange` | 交易所，可通过合约元数据补充，但必须无歧义 |
| `contract` | 实际到期合约；同时保存原始代码与规范化代码 |
| `target_lots` | 有符号整数手数，正数多仓、负数空仓、零平仓；表示目标持仓 |
| `trading_day` | 可选校验字段，夜盘按交易日历和 MDL TradDay 核对 |
| `strategy_id` | 可选，首版一个任务对应一个组合；多列策略可拆成独立实验 |

关键约定：

- 目标仓位不是每分钟买卖数量。例如当前 3 手、新目标 5 手，需求是增加 2 手。
- 如果文件时间是 bar 开始时间，但仓位使用该分钟收盘信息生成，`effective_ts` 必须映射到该分钟结束之后。映射规则写入运行配置。
- 缺失一行表示沿用上一目标；归零必须有明确的零值行。NaN、重复冲突和未知单位不能自动解释。
- 初始仓位默认零；非零初始仓位必须提供成本和今昨仓归属。跨日保持实际持仓；回测结束剩余持仓继续估值，另报未完成目标。
- 权重、金额、信号值不能直接当成手数。需要转换时，另行定义资金基数、因果价格和取整规则。
- 第一版要求实际合约。主连代码需要先用当时可知的主力映射展开，换月生成平旧开新订单，成本纳入结果。
- 输入按合约、时间校验；大文件采用分批读取或有界外部排序。注册后保存内容哈希，运行期间绑定同一份输入。

例：`2026-11-13T09:31:00+08:00, SHFE, rb2701, 5` 表示 09:31 起目标为多 5 手，与此前实际持仓和在途订单共同决定新增需求。

### 金额转手数：独立导出功能

```text
目标名义金额（人民币元） = 文件原值 × capital_cny（默认 5000000）
有符号理论手数         = 目标名义金额 / (参考价格 × 已验证合约乘数)
整数目标手数           = 向零取整(有符号理论手数)
```

默认 `capital_fraction` 模式使用用户指定本金；`notional_amount` 模式另用 `amount_unit_cny` 定义原始一个单位对应多少人民币元。默认向零取整，避免负值按 floor 取整后扩大空头仓位；其他取整规则如需支持，必须显式选择并写入配置。取整后的金额偏差单独展示。

参考价格默认选择目标生效时刻已经可用、且未过期的实际合约双边中间价，保存价格、源游标和可用时间，不能使用尚未结束分钟的收盘价。没有有效价格或元数据时标记待处理，不能伪造手数。主力映射和换算价格快照在导出时固定，跨模式比较使用同一份导出的按手目标。

默认每个输入时间点重新换算一次；即使金额不变，价格变化也可能导致整数手数变化，这部分调仓进入交易量和成本。以后如提供“仅目标金额变化或换月时重算”选项，作为不同转换规则记录。

输出 `target_lots.parquet`，至少包括：生效时间、交易日、品种、交易所、实际合约、原始值、人民币目标金额、参考价格及时间、乘数、目标整数手数、取整金额偏差和映射版本。理论目标差分与模拟实际成交差分分开保存。

### 主力切换与移仓换月

输入只描述品种目标，不包含自身采用的主力规则或换月指令，因此转换/回测需要主动生成移仓计划。默认复用现有 `local_rqdata_rule0` 的逐交易日映射：使用该交易日已生效的主力，不能提前使用当天收盘才产生的 `scheduled_next`。

- 主力的生效边界按交易日确定，有夜盘的品种通常从前一自然日夜盘开始；不能按自然日零点切换。
- 主力由旧合约 A 切到新合约 B 时，无论品种目标金额是否改变，都将 A 的目标设为零，并按 B 的当时参考价格重新换算目标手数。新旧手数不要求相等。
- 移仓根据实际持仓和在途委托执行：先协调旧有委托，再交给下述价差驱动的 maker-maker 算法分批迁移；平旧和开新可以交错进行。撤单到达前的晚到成交仍需纳入待平量。
- 换月使用独立的 `roll_execution=maker_maker_roll_v1`，普通仓位调整使用各自的 taker / maker 配置，两者可以分别指定。移仓两腿仍走同一套行情延迟、报撤单延迟和回报模型。
- 旧仓未平或新仓未开时，保留对应实际敞口，报告未完成移仓和临时敞口偏差。两合约必须各自在可交易时段和有效行情下成交。
- 平旧、开新分别收取对应手续费和执行价格成本，旧仓区分平今/平昨。原始合约之间的价差用于换月分析，不直接再扣作一笔现金手续费，也不能用连续复权价格模拟成交。
- `roll_events.parquet` 保存生效交易日、旧/新合约、移仓前实际仓位、目标手数、两边完成量与时间、费用及未完成原因。

### 换月固定算法：价差驱动 maker-maker

算法规则固定，调整参数即可复跑。输入为旧/新合约、旧仓实际手数、新目标金额/手数、执行窗口、价差阈值、单批数量、敞口容忍度和挂撤单参数。

**价差定义与挂单方向。** 记 A 为旧合约、B 为新合约，价差 `S = P_B - P_A`。首版用于同品种相同计量单位，合约规格先校验。

| 持仓方向 | 平旧 maker 挂单 | 开新 maker 挂单 | 候选挂单价差 | 有利方向 |
| --- | --- | --- | --- | --- |
| 多头换月 | 卖 A，挂卖一或更高 | 买 B，挂买一或更低 | `B_bid - A_ask`，含各自报价偏移 | 越低越有利 |
| 空头换月 | 买 A，挂买一或更低 | 卖 B，挂卖一或更高 | `B_ask - A_bid`，含各自报价偏移 | 越高越有利 |

两腿行情都必须是执行层已经收到的有效报价，要求各自不超过最大陈旧时间，并限制快照时间差。执行窗口开始后，在首个满足条件的时刻固定参考价差 `S_ref = B_mid - A_mid`；后续只用当时已知行情判断是否达到设定的改善阈值，不能回看全天最优价差。

对于 `d=+1` 的多头、`d=-1` 的空头，候选价差满足 `d × (S_quote - S_ref) <= -spread_improvement` 时，允许发起下一批。`spread_improvement` 使用明确的报价单位或 tick 网格。它是发起挂单的条件；两腿分别成交，不能据此保证最终成交价差。

**敞口控制。** 以有符号人民币名义敞口为默认口径：

```text
实际品种敞口 E(t) = q_A(t) × M_A × P_A(t) + q_B(t) × M_B × P_B(t)
敞口偏离 D(t)     = E(t) - 当前品种目标金额 T(t)
```

手数 q 带正负号，M 为已验证乘数，价格采用记录时刻可用的估值。最大偏离以绝对人民币金额或目标金额的比例配置；目标为零时使用绝对上限。手数相同不代表名义敞口完全相同，取整带来的偏差单独留痕。

执行层用已收到回报的仓位，加上所有未最终确认委托的可能成交区间约束新单；不能假设“撤单已发出”就释放敞口额度。挂两腿前，分别检查只成交任意一腿的情况是否仍在预算内。撮合侧另记真实仓位和真实峰值，不能把尚未送达的真实成交泄露给执行层。

**固定状态流程。**

1. 根据剩余旧仓和新目标确定一小批数量，以参考名义金额或可核对的合约数量配对，限制整数误差和单边成交可能产生的偏离。
2. 满足价差门槛且敞口预算允许时，分别提交平旧、开新的 post-only 单。两腿都是普通独立限价单，各自按严格击穿规则成交，不模拟原子价差成交。
3. 任意一腿先成交后，优先完成另一腿以恢复敞口；暂停会继续扩大偏离的挂单，并把其在途成交风险算入预算。例如多头先买到新仓，则优先卖旧仓；先卖掉旧仓，则优先买新仓。
4. 成对发起批次需要满足价差门槛；已有单腿成交后的敞口修复优先于继续等待价差。修复腿仍为 maker，可以按固定超时规则撤改至新的被动价格，但不能越过 post-only 约束。
5. 一批完成或风险解除后，再检查下一批。改价保持撤单确认后再发新单；回报延迟、拒单、晚到成交和跨段撤单均由共用状态机处理。
6. 到截止时间停止新批次并撤单，处理完晚到回报，保留未迁移旧仓和未完成新仓目标。首版不自动转 taker，也不强制假设两腿成交；报告未完成数量、截止敞口和偏离持续时间。

市场价格变化和回报延迟可能使真实敞口偏离预算，策略在收到信息后按固定规则修复；回测记录超限峰值与持续时间。严格零容忍无法同时保证独立 maker 两腿成交，应由参数可行性检查和结果如实反映。

完整策略回测中，分钟目标变化会更新 T(t) 和剩余新仓需求；目标缩减、归零或反向时优先撤销冲突委托并处理实际仓位。缩仓/反向部分单独标识，避免将策略调仓与换月收益混为一项。

### 独立换月回测与成本优化

新增任务类型 `roll_cost`，不要求加载整份分钟策略文件。可直接提供某品种的旧/新合约、起始持仓、固定目标敞口与换月窗口，单独评估固定算法；也可从完整回测中提取换月事件，保留相同起始状态和输入路径复跑。

单独实验默认固定目标敞口，比较参数时复用同一份初始仓位、目标、执行窗口、源帧、费用和延迟场景。可调整：价差改善阈值、每批名义金额/手数、最大敞口偏离、报价偏移、撤改间隔和单腿修复超时。延迟作为市场接入场景记录，不当作算法可以自行改善的参数。

基准至少包括同窗口的直接 taker 换月、受相同敞口预算约束但不设置价差门槛的 maker-maker；候选算法与基准必须同时报告完成率、执行成本和风险。参数搜索先用较早的换月事件选参，再在较晚事件上验证；运行中的决策不能访问后续行情。

每次独立实验输出：

- 两腿成交价量、最终成交价差、开平/平今费用，以及归属于换月的执行成本人民币和 bps。
- 旧仓关闭率、新仓目标完成率、完整换月完成时间、剩余旧仓和新仓缺口。
- 实际敞口偏离曲线、最大偏离、超限持续时间，以及 `∫|E(t)-T(t)|dt`（人民币×秒）作为风险暴露指标。
- 每批的挂单、单腿先成交、修复、撤单和回报游标，以便逐笔复核；两个不同时间的成交必须分别保留时间戳。

对于同数量单位的匹配部分，成交价差相对固定起点价差的成本为 `d × 匹配数量单位 × (S_fill - S_ref)`；乘数和计量数量用于换算人民币。新旧目标数量不同时，匹配部分和额外增减仓分别核算，不能把数量变化全部解释成价差优化。

上述价差成本与按腿计算的执行价格差是同一类成本的不同展示，不重复累加；跨期原始价差本身不等于一笔应直接扣除的现金损失。手续费另计。

优化目标是在明确的完成率和敞口约束下比较执行成本。未完成实验不能仅凭已成交部分价格较好就胜出；如补充截止时点剩余量的统一成交成本估算，它只作为单列对照，不能伪造为 maker 实际成交。窗口前的交易仅能在当时已知换月安排的前提下启用，默认从换月映射生效后开始。

### 交易成本估计：先估算，再用模拟成交核算

独立转换后提供快速估算：从整数目标差分生成假设调仓量，区分开仓、平今、平昨和移仓；结合明确费率及盘口/固定 tick 假设计算成本。结果注明假定完成的数量、参考价格时刻、费率来源及未知项，不能视作实际成交结果。

完整回测再按实际模拟成交量核算：

```text
单笔手续费   = 成交手数 × 每手费 + 成交价 × 乘数 × 成交手数 × 金额费率
执行价格成本 = 买卖符号 × 成交手数 × 乘数 × (成交价 - 本次目标的参考价)
```

费率按开平类型选择，费用采用来源规定的组合及舍入规则；价格改善保留为负成本。执行价格成本已经包含相对同一参考价的价差与价格移动，不能再叠加同口径滑点重复计算。移仓成本作为上述成交的分类小计，单独展示但不重复计入总成本。

maker 未成交量和机会成本另列，不因手续费较低就认定执行更优。费用来源缺失时保留未知及覆盖率。输出按笔、按分钟、按品种和全组合的人民币金额，并提供以对应参考成交名义金额为分母的 bps，分母和覆盖范围写入报告。

## 4. 时间与可配置延迟

采用离散事件虚拟时钟。ZMQ 负责传输，电脑实际收包速度和回放倍速只影响运行耗时。

```text
MDL 基准快照时刻 t_base ───────────────→ 撮合侧更新盘口
                  └─ 行情延迟 L_md ─→ 执行层可见行情
                                       └─ 决策耗时 L_compute
                                           └─ 报单延迟 L_order ─→ 订单到达撮合侧
                                                                  └─ 回报延迟 L_report
                                                                      → 执行层收到成交/撤单结果
```

时钟口径：

1. 保留 `ActionDay + UpdateTime` 的交易所时间、原始 `LocalTime`、`SeqNo` 和源行身份。
2. `t_base` 默认采用现有回放计划的“自然日 + 频道内前缀最大 LocalTime”，保持原始频道行序和既有跨频道合并顺序。不能按交易所时间重新排序。
3. 这是一套基于历史接收顺序的盘口代理，不是重建交易所内部时钟。`L_md` 默认表示在历史记录基础上额外增加的行情延迟；零额外延迟仍包含历史采集链路的延迟。
4. 第一版配置固定、非负的 `L_md / L_compute / L_order / L_cancel / L_report`。后续如需抖动，再引入明确分布、固定种子和保序策略。
5. 报单到达时间为 `t_decision + L_compute + L_order`；撤单按 `L_cancel` 到达。成交回报按 `L_report` 送达执行层。
6. 同一虚拟时刻先处理已存在订单对应的源行情，再处理外部目标/行情投递和指令；指令按稳定序号处理。由某帧触发的新 maker 单只能在源游标严格更晚的帧上成交。
7. 分钟边界、延迟使用自然时间；报价有效性和撮合受连续交易时段约束。午休压缩或不限速发送不改变虚拟时间里的午休长度。

必须分开维护“撮合侧盘口/实际账户”和“执行层已收到的行情/订单回报”。执行层只能读取后者。例如行情晚 300 ms 才送达，执行层据此挂单，但订单到达时必须按撮合侧那时的盘口判断，不能按旧盘口成交。

外部仓位的 `effective_ts` 不会因调整 `L_md` 自动改变。比较的是同一目标下的执行表现；离线生成目标仓位本身是否有未来信息，需要由输入的生成口径保证。

## 5. Taker 规则

默认采用有价格保护的 IOC；价格保护由执行层当前可见盘口及配置的允许 tick 偏移生成。

- 买单到达撮合侧时，按当时有效卖盘从低到高成交；卖单按有效买盘从高到低成交。
- 逐档检查价格保护，最多使用已有五档。超出五档或保护价的部分取消，之后由执行层按重试间隔决定是否再发单。
- 可用数量为该档已知数量乘 `depth_haircut` 后向下取整。同一快照内，多个子单共享剩余数量，不能反复吃同一份盘口。
- 下一帧提供新的盘口预算，这是快照模型的流动性补充假设；短周期重复吃单的结果必须结合参与率和敏感性参数评估。
- 缺失量、零价格、过期盘口和休市时段不能产生虚构成交。价格有效但数量未知，不视为无限可成交。
- 可配置每笔最大手数、重试间隔、允许滑点 tick 数；整数取整后的余量在后续订单处理。

例：买入 8 手，卖一 3500 / 3 手、卖二 3501 / 4 手，保护价 3501，则成交 7 手，剩余 1 手取消并记录缺口。

## 6. Maker 规则：严格击穿

默认按执行层可见的买一价挂买单、卖一价挂卖单，可配置向外偏移的 tick 数。到达撮合侧后采用 post-only：已经穿过对手价或与对手价相等时拒绝，不自动变成 taker。

| 方向 | 限价 | 后续帧的成交条件 | 模拟成交价 |
| --- | --- | --- | --- |
| 买入 | P | 本合约有效累计成交量增加，且该帧 `LastPrice < P` | P |
| 卖出 | P | 本合约有效累计成交量增加，且该帧 `LastPrice > P` | P |

`LastPrice == P` 仅触价，不成交。只有盘口移动、没有新增成交量，也不触发成交。同一源帧不能用于先观察、再挂单、再成交。

第一版采用最简单的数量假设：满足严格击穿条件后，该挂单剩余量全部按限价成交，模型标识为 `strict_trade_through_full_fill`。累计量复位、首个快照和断段之后先建立基线，不跨缺口认定有新增成交。

这属于快照上的击穿近似：2/4 Hz 行情会漏掉快照之间的击穿，且“击穿即全成”没有检验真实可成交数量，尤其不适合直接推断大仓位容量。报告保留这个假设及订单手数。后续如需数量约束，可增加按区间新增成交量设置上限的模型，另用模型版本区分。

撤单到达前仍可能成交。改价采用“撤单确认后再挂新单”，避免旧单、新单同时占用目标。挂单超时、下一分钟目标变化和连续交易段结束时触发撤单；跨休市处理固定为段末撤单，持仓继续保留。

第一版 taker / maker 分开运行同一份输入，便于比较。maker 到期剩余目标单独报告；如后续需要超时转 taker，再作为显式执行参数增加。

## 7. 仓位跟踪与下单规则

每次目标更新或订单回报到达时，执行层根据已知实际仓位、未成交委托和在途指令计算需求。未收到成交回报不代表订单没有成交，必须保留在途数量，避免重复补单。

最小订单状态覆盖：`created → in_flight → live → partially_filled → filled / cancelled / rejected / expired`。撤单请求和撤单到达分别留痕；拒单和晚到成交会触发重新计算。

下一分钟目标覆盖上一目标：先撤销与新目标冲突的未完成订单，确认后重算余量。反向目标先平仓、确认后开反向仓，区分开仓、平今和平昨手续费。

执行层因子或规则如需扩展，只负责下单、等待、撤单、改价、数量和保护价，读取已送达的行情，不改变外部目标仓位。第一版先实现以上固定规则和参数。

## 8. CN 数据、交易时段与记账

- 只使用 MDL msg 层，覆盖起点为 2023-12-07，具体可用日期运行前检查。交易日按 TradDay，夜盘跨自然日和周六目录复用现有回放选择逻辑。
- 默认只接受已完成的源文件；输入仍在追加时拒绝作为正式回测。研究性 partial 运行需显式开启，并在报告标识覆盖边界。
- 郑商所三位码按交易日规范化。撮合只用实际合约原始报价；复权或连续合约价格可用于研究对照，但不能用于模拟成交。
- 时段模板和交易日历固定版本，节假日特殊安排用明确覆盖；不从行情缺口猜休市。交易段结束后的快照可留作审计，不生成段外成交。
- 乘数只读权威表；tick、涨跌停和盘口有效性均校验。价格用整数 tick，资金采用固定精度，明确费用舍入规则。
- 手续费区分开仓、平仓和平今。reference 的 OpenCTP 费用属于经纪商参考，`historicalExact=false`；历史缺失不能用最新费率悄悄补齐。用户可提供按日期生效的费率表，或显式选定假设快照。
- 没有费用依据时，费用相关净指标不可用；只有用户明确设为零费用时，才按零费用计算。
- 今昨仓在交易日切换时转换，不按自然日零点转换；初始仓位和历史成交的持有成本参与盈亏核算。
- 第一版提供成交、费用、已实现盈亏、持仓浮盈亏和 MTM 权益。配置初始资金后才能计算收益率；没有可靠结算价时，不把 MTM 权益描述为完整结算资金账。
- 保证金可按用户选定费率做静态占用估算，首版不据此模拟强平。账户权益满足：`初始权益 + 已实现盈亏 + 未实现盈亏 - 已确认费用`，期货开仓不扣除整个名义本金。
- 估值行情及其时间戳留痕；跨休市延用的估值必须标出陈旧程度，估值价格不能拿来撮合。

因果性检查中特别处理现有分钟表：`mid_price` 是分钟末值；大小单阈值可能使用完整自然月信息。它们不能作为分钟开始时已知的下单因子。需要在线因子时，从已投递的 MDL 增量计算，或导入带明确可用时间的因子文件。

## 9. ZMQ 接入与确定性

建议由回测 worker 使用 `mdl_replay` 库创建专用回放会话，与自己建立的回放计划绑定，避免占用或修改生产回放服务配置。

1. 按交易日准备计划，接收端先订阅 `mdl.*` 和 `replay.ctl`，确认就绪后手动 start；使用无损发送，`repeat=1`。
2. 通过同一份只读计划，按接收帧序号关联 `自然日、频道、源行号、规范化 LocalTime`。帧本身保持原样；源游标作为回测内部元数据，不拼进原始帧。
3. 接收原始帧后进入虚拟事件调度器。用下一帧的基准时间作为推进边界，将行情、延迟投递、目标、报撤单和回报合并处理。等下一帧时不能凭本机时间提前推进。
4. 队列达到上限就通过 ZMQ 背压等待；延迟事件超出内存预算时落到 NVMe 临时段。不会通过丢行情释放资源。
5. 多日回测逐日准备计划，账户跨日继承，不一次加载全历史。源身份和内容摘要写入 manifest；缓存内容在任务完成前固定引用，复跑时重新核验。
6. 源 end 到达后核对接收数、发送数与计划数，继续处理到回测截止时刻已发生的订单结果和相应晚到回报，再确认释放连接。边界以外不继续交易；剩余委托与目标单列报告。

同一输入、配置、源数据、模型版本的成交和账户结果应完全一致。倍速、暂停、机器繁忙和 socket 背压不能改变结果；运行耗时和日志时间不纳入结果一致性哈希。

## 10. 结果与工作台

每次运行保存：

```text
runs/<run_id>/
  config.toml            # 本次所有显式配置及展开后的默认值
  manifest.json          # 输入、源身份、元数据、代码和撮合模型版本
  target_lots.parquet    # 金额转换后的固定整数目标，含换算价格和主力身份
  cost_estimate.parquet  # 按理论目标差分和显式假设计算的快速成本估计
  roll_events.parquet    # 平旧开新的移仓计划与完成情况、成本分类
  roll_exposure.parquet  # 换月实际敞口、执行层已知敞口及偏离
  roll_batches.parquet   # 双腿批次、成交价差、单腿修复和完成情况
  orders.parquet         # 报单、撤单、拒单、过期及其时间和原因
  fills.parquet          # 成交价量、费用、源帧游标及触发依据
  positions.parquet      # 分钟目标、实际仓位、已知仓位、未完成量
  equity.parquet         # MTM 权益、已实现/未实现盈亏、费用、估值时刻
  execution.parquet      # 目标批次完成率、耗时、价格差和剩余需求
  summary.json           # 指标及数据覆盖、费用/成交假设
```

关键指标包括：毛/净盈亏、回撤、成交额、费用、目标完成率、仓位偏离、完成耗时、拒单及未成交原因。执行价格差采用明确的参考时刻和价格；只有完整有效的双边盘口才能计算 arrival mid，计算不了时保留未知和覆盖率。

maker / taker 对比同时展示相同目标下的成交数量、费用和未成交量，不能只比较已成交部分的均价。未成交机会成本与已成交价格差单独计算和展示，参考窗口固定。

工作台提供四个页面：输入预览与校验、创建实验、运行列表与取消、结果详情与模式对比。创建实验时可批量选择模式及延迟参数，展开成多个独立 run 并串行排队。

创建实验支持完整策略执行回测和独立换月成本回测两种任务。换月详情提供新旧合约价差、两腿成交、迁移进度和敞口偏离联动图，并以成本、完成率、风险并列表格比较参数。

拟定 API：注册/检查本地 Parquet、创建 run、查询状态、取消、读取结果、创建比较。先支持本机路径导入；交互上传可在页面阶段按流式实现。任务状态明确区分 `queued / preparing / running / completed / failed / cancelled / interrupted`，未完成结果不能显示为成功。

## 11. 资源与统一调度

建议初始资源预算为一个重任务、最多 8 个计算/I/O 工作线程、16 GiB 进程组内存，实际峰值在真实数据验收后确认。行情、仓位和输出按日/批次处理，明细分批写 Parquet，页面按需分页读取。

现有 MDL 冷构建会并行构建多频道，并将单文件读入内存，不能直接认为符合上述预算。回测适配器需先逐分片预热、每分片限制构建线程，再准备和发布；记录源变化并核对峰值。必要时在 MDL 增加可配置的分片构建并发上限，按其既有规则验证帧和顺序一致。

生产接入建议新增固定 `[[job]] cn-backtest-worker`，无定时触发，由页面手动入队。工作台自己的 SQLite 只保存待办 run；worker 每次领取一个 run 后退出，再通知统一队列处理下一个，从而与 cn-daily / lseg-daily 等串行。

现有调度器只支持固定任务名，需要补齐“待办持久化、完成后再次唤醒、崩溃后的领取恢复、按 run 取消”衔接。worker 启动期间若又有 run 入队，不能因同名任务去重而丢失唤醒。启动和每次结束都核对待办；正在运行的大任务按现有约束完成或取消，后续任务才启动。CLI 阶段也遵守重任务不并发的要求。

## 12. 实施顺序与验收

| 阶段 | 交付内容 | 验收标准 |
| --- | --- | --- |
| P0：输入与口径 | 固定金额单位/倍率、字段映射、目标生效时间、初始仓位、费用、延迟含义和 maker 全成假设 | 已完成实际文件结构和时间口径检查；其余参数在运行前显式配置 |
| P1a：按手仓位与成本估计 | 独立 CLI：金额映射到当日主力、整数取整、换月计划、按手 Parquet 和快速成本估计 | 样例逐条可核算；取整偏差可见；金额不变而主力变化时也生成平旧开新需求 |
